# RAG Eval Platform UI/UX 设计规范

## 文档状态

- 状态：已确认的 UI 设计基线
- 日期：2026-09-09
- 适用范围：首个端到端 MVP 管理后台
- 关联 PRD：[MVP PRD](../superpowers/specs/2026-09-09-rag-eval-platform-mvp-prd.md)
- 低保真原型：[后台低保真原型](../prototypes/rag-eval-admin-low-fi.html)

## 1. 设计目标

RAG Eval Platform 是面向 RAG/AI 工程团队的 B2B 管理后台。界面需要同时满足：

- 长时间阅读表格、Trace 和评测结果时的舒适度；
- 高信息密度下的清晰层级；
- 从总体指标下钻到具体失败样例；
- 复杂异步任务的状态可见性；
- 通过 Adapter、数据集版本和实验快照表达可复现性；
- 适合开源项目自部署，不制造厂商绑定感。

设计原则：专业、克制、可解释、可追溯、可访问、可扩展。

## 2. 视觉方向

### 2.1 默认主题：Light / Data Workspace

- 浅色中性画布；
- 深色侧边导航；
- 信任蓝作为主操作色；
- 橙色只用于行动强调、风险和需要关注的状态；
- 白色卡片承载指标、表格和表单；
- 使用网格和明确的边界保持数据密集页面的秩序。

### 2.2 可选主题：Dark / AI Operations

- 深色画布和深色卡片；
- 蓝色高亮用于交互和链路定位；
- 适合夜间工作、实时运行和 Trace 调试；
- 不改变信息架构、字段、交互和状态语义。

深色主题是同一套设计 tokens 的主题变体，不单独设计一套页面。

### 3.2 字体

- UI 主字体：Plus Jakarta Sans；
- 中文回退：`Noto Sans SC`、系统无衬线字体；
- 数据、Trace JSON、Endpoint 和代码：Fira Code；
- 标题使用 600-700 字重；
- 正文使用 400-500 字重；
- 辅助信息不低于 12px；
- 页面正文默认 14px，密集表格可以使用 12-13px；
- 不使用过度装饰性的字体和字体组合。

### 3.3 间距与尺寸

- 基础间距单位：4px；
- 页面桌面端内边距：24-32px；
- 卡片内边距：16-20px；
- 组件间距：8、12、16、24px；
- 侧边导航宽度：约 220-240px；
- 顶部栏高度：56-64px；
- 小控件高度：32-36px；
- 主要按钮高度：36-40px；
- 卡片圆角：8px；
- 弹窗圆角：12px；
- 状态标签圆角：999px。

### 3.4 阴影与动效

- 默认使用边框而不是重阴影区分层级；
- 浮层和弹窗可以使用轻微阴影；
- hover 使用颜色、透明度或边框变化，不改变布局尺寸；
- 交互过渡使用 150-300ms；
- 长任务使用 skeleton 或 spinner；
- 支持 `prefers-reduced-motion`；
- 不使用影响数据阅读的持续动画。

## 4. 全局应用壳

### 4.1 桌面端

```text
深色左侧导航
├── 工作台
├── 数据资产
├── 评测实验
├── 分析诊断
└── 系统管理

白色顶部栏
├── 组织/项目切换
├── 全局搜索
├── 通知
└── 用户菜单

主内容区
└── 页面标题 + 操作区 + 内容面板
```

### 4.2 导航行为

- 一级菜单展开状态清晰；
- 当前页面使用背景、文字和左侧标记表达；
- 带数量的菜单显示待处理数量；
- 面包屑用于表达组织、项目和当前页面；
- 页面刷新后保留当前项目和筛选条件；
- 无权限菜单不显示或显示为不可用，并提供说明。

### 4.3 响应式

- 320px：单列内容，侧边栏收起为抽屉；
- 768px：两列卡片和可横向滚动表格；
- 1024px：保留侧边导航，主要面板开始自适应；
- 1440px：展示完整三栏 Trace、审核和配置布局；
- 不为移动端重复维护一套完全不同的业务内容；
- 表格在窄屏使用横向滚动，并保持列标题可理解。

## 5. 页面设计规范

### 5.1 工作台 Dashboard

首屏结构：

1. 页面标题、说明、导出报告和创建评测；
2. 证据命中率、Faithfulness、本周实验、待审核样例四个 KPI；
3. 质量趋势图与待处理事项；
4. 最近实验与失败原因分布。

设计要求：

- KPI 必须带时间范围或对比基线；
- 图表必须支持 hover、图例和下钻；
- 待处理事项提供直接行动入口；
- 失败原因分布链接到失败案例或 Trace；
- 没有数据时显示下一步行动，而不是空白。

### 5.2 文档库

核心结构：统计卡片、筛选栏、文档表格、上传提示。

表格必须展示名称、类型、版本、解析状态、关联评测集和更新时间。解析中、解析失败、解析成功分别使用进度、失败原因和可用状态表达。上传按钮在页面标题区保持稳定位置。

### 5.3 审核队列

使用三栏审核工作台：

- 左栏：候选问题队列和审核状态；
- 中栏：问题、参考答案、证据和属性编辑；
- 右栏：自动质量检查、置信度、审核记录和操作。

通过、驳回、需修改和跳过必须有不同的确认语义。证据必须显示来源文档和页码/段落定位。支持键盘快捷键，但不能让快捷键成为唯一操作方式。

### 5.4 Pipeline 接入

使用左右分栏：

- 左栏：Adapter 列表、类型、版本、Trace 级别和可用状态；
- 右栏：Adapter 配置、连接测试、响应格式校验和保存。

HTTP Adapter 和 Python SDK Adapter 使用相同的配置概念和数据模型。最小 Trace 与深度 Trace 需要明确说明能力差异。API Key 只显示脱敏内容。

### 5.5 实验任务

使用四步向导：

1. 选择评测集和版本；
2. 选择 Adapter、模型和指标；
3. 设置运行参数和 Trace 保存级别；
4. 检查摘要并启动。

右侧或顶部展示实验摘要。启动前展示样例数量、预计耗时和成本。实验开始后锁定评测集、Adapter、模型、参数和指标规则。

### 5.6 指标看板

采用“总体 KPI → 趋势 → 阶段表现 → 分类下钻”的层级：

- KPI：Recall@K、MRR、Faithfulness、Citation Correctness、P95 延迟；
- 趋势：当前实验与基线；
- 阶段：召回、重排、上下文、生成；
- 分类：问题类型、难度、文档和标签。

推荐图表：

- 趋势：折线图；
- 实验对比：多序列折线或分组条形图；
- 阶段表现：水平条形图；
- 检索链路：漏斗或 Sankey，仅在阶段数据足够时使用。

图表要同时提供文本/表格摘要，避免颜色成为唯一信息来源。

### 5.7 Trace 分析

三栏布局：

- 左栏：阶段时间线和耗时；
- 中栏：当前阶段详情、候选结果、上下文和原始响应；
- 右栏：样例评测结果、标准答案对照、运行信息。

标准证据命中、未命中和被重排排除必须可视化。诊断建议要标记为建议，并展示依据。Trace 缺失阶段必须显示“未提供”，不能用空内容伪装完整链路。

### 5.8 项目与成员

左侧成员表格，右侧角色权限说明，下方提供快速邀请。角色说明必须使用用户能理解的业务动作，而不是只列抽象权限名称。

### 5.9 模型与服务

左侧服务列表，右侧配置表单。展示服务用途、模型名、Base URL、脱敏 Key、连接测试、可用范围和成本。支持 OpenAI-compatible 服务，必须明确数据发送边界和 Key 安全策略。

## 6. 状态与反馈

### 6.1 必备状态

每个异步页面都必须支持：

- 初始空状态；
- 加载状态；
- 排队中；
- 处理中；
- 成功；
- 部分成功；
- 失败；
- 已取消；
- 权限不足；
- 无筛选结果。

### 6.2 错误信息

- 错误说明问题是什么；
- 提供下一步动作；
- 标明是否可以重试；
- 使用 `role="alert"` 或 `aria-live` 通知辅助技术；
- 不只使用红色边框表达错误。

### 6.3 空状态

空状态必须包含：当前对象、为什么为空、下一步操作。例如“还没有评测集。上传一份文档后即可生成候选评测数据”。

## 7. 可访问性

- 正文和交互元素满足至少 4.5:1 对比度；
- 所有表单控件有可见 label；
- 所有交互元素支持键盘访问和可见 focus；
- 状态不只依赖颜色；
- 表格有正确的表头语义；
- 图表提供文本摘要或数据表；
- 弹窗打开后管理焦点，关闭后恢复焦点；
- 支持减少动效；
- 页面在 320px 宽度不产生不可控的横向滚动。

## 8. 图标与图表规范

- 使用统一 SVG 图标集，例如 Lucide 或 Heroicons；
- 不使用 emoji 作为界面图标；
- 图标尺寸保持 14/16/20px 级别；
- 图标必须配合 tooltip 或可见文本，不单独承载关键语义；
- 图表必须有图例、单位、时间范围和样本数；
- 多序列图表同时使用颜色、线型或标记区分；
- 失败和警告的颜色不能使用过度饱和的纯红/纯黄占满页面。

## 9. 前端实现建议

具体前端框架尚未确定。实现时应保持设计系统与框架解耦：

- 颜色、间距、圆角和字号使用 tokens；
- 表格、状态标签、指标卡、筛选器、步骤条、时间线和 Trace 区块作为可复用组件；
- 页面组件只负责组合，不复制业务状态逻辑；
- 组件状态覆盖默认、hover、focus、disabled、loading、error 和 empty；
- 图表数据和图表外观分离；
- 设计稿中的示例数据不能进入生产默认数据；
- 视觉回归和可访问性检查加入 CI。
