## 1. 产品概述

RAG Eval Platform 是一个面向 RAG/AI 工程团队的开源评测管理后台。它从原始知识文档开始，构建可追溯、可审核、可版本化的评测集，接入用户已有的 RAG Pipeline，执行可复现实验，并通过分阶段指标和 Trace 定位检索链路问题。

平台不替代企业知识库、向量数据库或用户自己的 RAG 框架，不绑定某一家 LLM、Embedding 或 Reranker 厂商。平台的核心价值是把“评测数据工程、Pipeline 实验、阶段诊断和回归”串成一个可复现的质量闭环。

## 2. 产品目标

### 2.1 MVP 目标

用户可以在一个项目中完成：

1. 上传 PDF、Word、Markdown 或 TXT 文档；
2. 生成候选问题、参考答案和标准证据；
3. 审核候选数据并发布评测集版本；
4. 接入一个 HTTP Adapter 或 Python SDK Adapter；
5. 选择评测集、Pipeline 和模型配置创建实验；
6. 批量运行评测并查看运行状态；
7. 查看检索、生成和工程指标；
8. 打开单条失败样例的 Trace，定位可能的失败阶段。

### 2.2 非目标

首个 MVP 不包含：

- 在线编辑复杂文档；
- 企业知识库生产管理；
- 自研向量数据库；
- 替代 LangChain、LlamaIndex、Dify 或用户自研 RAG；
- 多组织 SaaS、计费和商业化租户管理；
- 复杂工作流编排；
- 将自动生成答案直接视为 Gold Dataset。

## 3. 用户与权限

### 3.1 目标用户

- RAG 工程师：调试切分、查询改写、召回、重排和上下文组装；
- AI 应用工程师：对比不同模型和 Pipeline 配置；
- LLM 平台工程师：维护 Adapter、模型服务和评测环境；
- 技术负责人：查看质量趋势、实验结果和回归风险。

### 3.2 组织模型

首个版本采用单组织、多项目模型：

```text
组织
└── 项目
    ├── 文档
    ├── 评测集
    ├── Pipeline Adapter
    ├── 实验任务
    ├── Trace
    └── 评测报告
```

资源默认按项目隔离。架构需要为未来多组织扩展保留组织标识和权限边界，但 MVP 不实现计费和租户运营功能。

### 3.3 角色

| 操作 | 管理员 | 编辑者 | 查看者 |
|---|---:|---:|---:|
| 查看项目 | ✓ | ✓ | ✓ |
| 上传文档 | ✓ | ✓ | - |
| 编辑评测集 | ✓ | ✓ | - |
| 审核数据 | ✓ | ✓ | - |
| 配置 Adapter | ✓ | ✓ | - |
| 创建/启动实验 | ✓ | ✓ | - |
| 查看 Trace 和报告 | ✓ | ✓ | ✓ |
| 管理成员 | ✓ | - | - |
| 管理模型服务 | ✓ | - | - |
| 删除项目 | ✓ | - | - |

```text
工作台

├── 文档库
├── 评测集

评测实验
├── Pipeline 接入
├── 实验任务
└── 运行记录
分析诊断
├── 指标看板

└── 失败案例
系统管理
├── 模型与服务
├── 项目与成员
└── 系统设置
```

### 4.1 全局能力

- 组织切换；
- 项目切换；
- 全局搜索；
- 通知；
- 当前用户菜单；
- 面包屑；
- 页面级权限控制；
- 异步任务状态提示。

所有列表页面必须处理加载、空数据、无筛选结果、错误、权限不足、分页和批量操作状态。

## 5. 核心业务流程

```text
创建项目
→ 上传文档
→ 解析文档
→ 生成候选评测数据
→ 自动质量检查
→ 人工审核
→ 发布评测集版本
→ 配置 Adapter
→ 测试连接
→ 创建实验任务
→ 批量执行
→ 查看指标
→ 查看失败 Trace
→ 沉淀失败案例/回归数据
```

异步任务统一使用以下状态：

```text
未开始 → 排队中 → 处理中 → 成功
                         ├→ 部分成功
                         ├→ 失败
                         └→ 已取消
```

## 6. 功能需求

### 6.1 工作台

#### 目标

提供项目级概览，让用户快速知道评测资产、实验运行和质量风险。

#### 内容

- 评测集数量和最新版本；
- 待审核数量；
- 最近实验和执行状态；
- 证据命中率、Faithfulness 等核心指标趋势；
- 最近失败案例；
- 快捷入口：上传文档、创建评测集、接入 Pipeline、创建实验。

#### 验收标准

- 所有数字都能下钻到对应列表；
- 不存在数据时展示引导操作，而不是空白页面；
- 指标展示必须标明时间范围、样本数和关联实验。

### 6.2 文档库

#### 字段

- 文档名称、文件类型、文件大小；
- 文档版本、来源类型、上传人、上传时间；
- 解析状态、错误信息、内容摘要；
- 关联评测集。

#### 状态

```text
上传中 → 等待解析 → 解析中 → 解析成功
                              └→ 解析失败
```

#### 操作

- 上传单个或多个 PDF、Word、Markdown、TXT；
- 查看详情和解析结果；
- 查看文档版本；
- 重新解析；
- 从文档生成候选评测数据；
- 删除文档。

#### 规则

- 不支持的格式在上传前提示；
- 重复文件不能静默覆盖；
- 解析失败必须显示原因和重试入口；
- 被已发布评测集引用的文档删除前必须二次确认；
- 文档删除不能破坏历史评测集版本。

### 6.3 评测集

#### 单条数据字段

- 问题；
- 问题类型；
- 难度；
- 参考答案；
- 标准证据；
- 来源文档、文档版本、页码或段落位置；
- 自动检查结果；
- 人工审核状态；
- 置信度；
- 创建方式；
- 最后修改人。

#### 评测集状态

```text
草稿 → 审核中 → 可发布 → 已发布 → 已归档
```

#### 规则

- 已发布版本不可直接修改；
- 修改已发布数据必须创建新版本；
- 每次实验必须绑定明确的评测集版本；
- 版本需要保存生成配置和审核记录；
- 只有审核通过的数据可以进入可发布版本。

### 6.4 审核队列

审核者在一个页面完成：

```text
查看问题
→ 查看参考答案
→ 查看标准证据和原文位置
→ 检查一致性
→ 修改或补充
→ 通过 / 驳回 / 需修改 / 跳过
```

页面必须同时展示原始文档片段、问题、答案、证据、自动检查、修改历史和审核意见。

所有人工修改必须保留审计记录。批量通过不能绕过必要的质量检查。

### 6.5 Pipeline 接入

#### 接入类型

- HTTP Adapter；
- Python SDK Adapter。

两种 Adapter 使用同一套请求、响应和 Trace 数据模型。

#### Adapter 基础字段

- 名称；
- 类型；
- 服务地址或 SDK 标识；
- 认证方式；
- 超时时间；
- 重试次数；
- 版本号；
- 所属项目；
- 状态；
- 最后测试时间。

#### 最小响应

```json
{
  "answer": "最终回答",
  "citations": [],
  "usage": {
    "latency_ms": 800,
    "input_tokens": 1000,
    "output_tokens": 100
  }
}
```

#### 深度 Trace 响应

```json
{
  "trace": {
    "rewritten_queries": [],
    "retrieval": {
      "vector": [],
      "keyword": []
    },
    "merged_results": [],
    "reranked_results": [],
    "context": []
  }
}
```

#### 接入流程

```text
新增 Adapter → 填写配置 → 测试连接 → 验证响应格式 → 保存 → 启用
```

最小接入只要求答案、引用和运行指标；深度接入再提供查询改写、召回、合并、重排、上下文和生成阶段。

#### 安全与版本规则

- API Key 不在页面明文回显；
- 日志中不得记录完整 API Key；
- Adapter 不可用时不能启动正式实验；
- 实验保存执行时的 Adapter 配置快照；
- Adapter 版本变化必须可追踪。

### 6.6 实验任务

#### 配置项

- 实验名称；
- 评测集及版本；
- Pipeline Adapter 及版本；
- 模型服务；
- Top-K；
- 并发数；
- 超时时间；
- 重试策略；
- 指标集合；
- 是否保存完整 Trace；
- 实验备注。

#### 状态

```text
草稿 → 等待运行 → 运行中 → 已完成
                         ├→ 部分失败
                         ├→ 已失败
                         └→ 已取消
```

实验开始后，评测集版本、Adapter 版本、模型配置、实验参数和指标规则不可直接修改。修改必须创建新的实验任务。

### 6.7 运行记录

展示总样例数、已完成数、成功数、失败数、跳过数、进度、耗时、预计剩余时间、API 成本、错误类型和可重试样例。

单条样例失败不能导致整个实验静默失败。任务必须支持取消、失败样例重试和中断后的恢复或重新执行。

### 6.8 指标看板

#### 检索指标

- Recall@K；
- Precision@K；
- Hit Rate；
- MRR；
- nDCG；
- 证据命中率；
- 父块覆盖率；
- 多路检索互补率。

#### 生成指标

- Answer Correctness；
- Faithfulness；
- Citation Correctness；
- Context Precision；
- Context Recall；
- 拒答准确率。

#### 工程指标

- 平均、P50、P95 延迟；
- Token 消耗；
- API 成本；
- 失败率；
- 超时率。

看板支持按实验、问题类型、难度、文档和标签筛选，支持多实验对比和报告导出。任一指标必须可以下钻到样例。

### 6.9 Trace 分析

```text
原始问题
→ 查询改写
→ 各路召回
→ 结果合并
→ 重排
→ 上下文组装
→ 模型生成
→ 最终答案
```

页面支持阶段展开/收起、查看原始文本、标记标准证据、显示失败阶段、跳转同类失败、复制 Trace JSON 和查看 Adapter 原始响应。

Trace 不完整时必须明确显示缺失阶段，而不是伪造完整链路。

### 6.10 失败案例

#### 失败分类

- 标准证据未召回；
- 查询改写错误；
- 向量检索失败；
- 关键词检索失败；
- 混合检索融合失败；
- 重排错误；
- 上下文缺失；
- 答案不忠实；
- 引用错误；
- 拒答错误；
- Adapter、超时或基础设施错误。

#### 状态

```text
待分析 → 已归类 → 已加入回归集 → 已修复待验证 → 已关闭
```

失败案例支持查看详情、指定原因、备注、分配负责人、加入回归评测集、忽略和查看历史实验表现。

系统生成的诊断只能标记为“建议”，必须展示证据来源，不能替代人工判断。

### 6.11 模型与服务

第一版支持配置 OpenAI-compatible 服务，包括 Base URL、API Key、模型名、服务类型、超时、重试和启用状态。后续通过 Provider Adapter 扩展原生厂商协议。

API Key 加密存储或通过安全配置注入；连接测试不得默认保存用户真实问题内容。

### 6.12 项目与成员

支持创建、编辑、归档项目，邀请成员、分配角色、修改角色、移除成员和查看最近活动。

### 6.13 系统设置

第一版支持默认并发数、超时时间、重试次数、数据保留策略、日志级别、时区、语言、默认分页大小和匿名遥测开关。所有默认配置允许项目级覆盖。

## 7. 可追溯性与数据关系

```text
原始文档
  ↓
文档片段
  ↓
候选评测数据
  ↓
人工审核
  ↓
评测集版本
  ↓
实验任务
  ↓
样例结果与 Trace
  ↓
失败案例/回归数据
```

任一实验结果都必须能追溯到：评测集版本、原始文档版本、Adapter 版本、模型配置、实验参数、指标版本和平台版本。

## 8. 审计、安全与非功能需求

### 8.1 审计日志

登录、成员权限、文档、评测集、Adapter、模型服务、实验和系统配置等变更必须记录操作人、时间、操作类型、资源、结果和失败原因。

### 8.2 可靠性

- 所有外部调用必须有超时上限；
- 支持重试、取消和资源释放；
- 单条失败必须可分类；
- 任务中断后可以恢复或重新执行失败样例；
- 失败不能被静默吞掉。

### 8.3 安全与隐私

- 不提交和不记录真实密钥；
- 防止 SSRF、路径穿越和恶意文件上传；
- 限制文件大小、解析资源和并发；
- 明确哪些数据会发送给模型服务；
- 用户数据默认不上传到平台外部服务；
- 所有输入进行校验，敏感字段脱敏展示。

### 8.4 开源工程要求

- 提供 Docker Compose 本地部署方式；
- 提供 `.env.example`，不包含真实密钥；
- 提供数据库迁移、API 文档、开发启动说明和最小示例；
- CI 执行格式化、静态检查、类型检查、测试、构建和安全检查；
- 依赖许可证和安全公告可审计；
- 公共契约有版本策略和迁移说明。

## 9. MVP 验收标准

### 必须通过

- 用户能创建项目并管理成员角色；
- 用户能上传并解析支持的文档；
- 用户能生成候选评测数据；
- 用户能审核并发布评测集版本；
- 用户能接入 HTTP Adapter 和 Python SDK Adapter；
- 用户能创建、运行、取消和重试实验；
- 用户能查看检索、生成和工程指标；
- 用户能打开单条样例的 Trace；
- Trace 缺失阶段有明确提示；
- 结果可追溯到所有关键版本和配置；
- API Key 不在页面和日志中泄漏；
- 核心流程具备自动化测试和可部署文档。

### 质量门禁

```text
功能测试
+ 权限测试
+ Adapter 契约测试
+ 异步任务测试
+ 安全检查
+ 格式化/静态检查/类型检查
+ 构建检查
+ Docker Compose 启动验证
```

## 10. 原型范围

低保真原型覆盖以下关键页面：

- 工作台；
- 文档库；
- 评测集和审核队列；
- Pipeline 接入；
- 实验任务和运行记录；
- 指标看板；
- Trace 详情；
- 项目与成员。

原型阶段只验证信息架构、页面层级、关键任务路径和状态反馈，不确定颜色、字体、品牌风格和最终组件细节。视觉设计将在本 PRD 和低保真原型通过审阅后单独进行。
